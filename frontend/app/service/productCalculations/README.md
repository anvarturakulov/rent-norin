## Как работает новая архитектура:

### 1. Пользователь заполняет готовую продукцию
- Добавляет товары в верхнюю таблицу документа
- Указывает количество каждого товара

### 2. Нажимает кнопку "Заполнить материалы"
- Кнопка появляется только после добавления готовой продукции
- Система проверяет наличие существующих материалов

### 3. Система собирает информацию по калькуляциям
- Загружает калькуляции для каждого продукта через API
- Группирует материалы по ID
- Суммирует количества одинаковых материалов

### 4. Определяет себестоимость материалов
- Получает остатки со склада (receiverId из документа - склад материалов)
- Рассчитывает среднюю себестоимость: `totalSum / totalQuantity`
- Если нет остатков на складе, использует себестоимость 0

### 5. Заполняет нижнюю таблицу материалов
- Создает записи типа `expense` для каждого материала
- Указывает количество, себестоимость и общую сумму
- Получает реальные остатки со склада

### 6. Рассчитывает общую стоимость
- Суммирует стоимость всех материалов
- Распределяет на готовую продукцию пропорционально количеству
- Обновляет `costPrice` и `costTotal` для готовой продукции

## Преимущества новой архитектуры:

1. **Производительность**: Меньше запросов к серверу
2. **Гибкость**: Легче добавлять новую логику расчета
3. **Отзывчивость**: Мгновенное отображение результатов
4. **Прозрачность**: Все расчеты видны в консоли браузера
5. **Надежность**: Лучшая обработка ошибок

## API эндпоинты, которые используются:

- `GET /api/product-calculations/product/{productId}` - получение калькуляций
- `GET /api/reports/priceAndBalance?schet=S10&firstSubcontoId={warehouseId}&secondSubcontoId={materialId}` - остатки и средняя себестоимость материалов
- `PATCH /api/documents/update/{documentId}` - сохранение документа

## Исправления в архитектуре:

### ✅ Исправлена проблема с определением готовой продукции
- Готовая продукция теперь правильно определяется как `tableType: undefined` или `tableType: 'income'`
- Пересчет себестоимости теперь работает корректно

### ✅ Убрана логика поиска последней цены закупки
- Используется только средняя себестоимость со склада
- Если нет остатков, себестоимость = 0 (как и должно быть)

### ✅ Правильное определение складов
- `receiverId` - склад материалов (откуда берем для расчета себестоимости)
- `receiverId` - склад готовой продукции (куда поступает)
- Себестоимость материалов берется со склада получателя (`receiverId`)

## Обработка ошибок:

- Проверка наличия калькуляций для продукции
- Валидация количества продукции
- Обработка ошибок сети
- Информативные сообщения пользователю
